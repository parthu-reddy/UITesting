# Quick Tunnel SSE validation boundary — 2026-10-02

Cloudflare's current [Quick Tunnel limitations](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) explicitly exclude Server-Sent Events. Checking a200/text-event-stream handshake on trycloudflare.com cannot prove live tracking works.

For the same owned retained Dev order, the public path had zero response chunks during eight actual rider GPS frames. An authenticated browser through a temporary localhost SSH forward to the Oracle UI origin received four chunks/425bytes, connected and two location events, and rendered two GPS-matching courier positions. Delivery then completed and read-only postconditions confirmed released assignment and idle riderOFFLINE. Browser login still used Dev Autofill. No provider bypass, fabricated event, server reset or cleanup was used.

Nginx buffering and its nested proxy-handler404 were separate application proxy defects and were corrected/deployed as772f50d. Origin success proves that path; it does not prove the unsupported public edge. The user explicitly requested ignoring SSE for now, so public SSE remains deferred without a tunnel migration or further blocking of other features.
