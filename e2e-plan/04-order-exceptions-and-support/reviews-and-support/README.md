# reviews-and-support

Status: **not production-ready yet**. On 2026-09-29, customer and restaurant review flows, My Reviews, and the populated restaurant feedback/aggregate passed against the deployed development environment. The rider review step exposed a UI bug: completed-order history was not fetched while the rider was Offline. A direct authenticated history request returned the delivered test order with HTTP 200, confirming this is not a backend history-query failure. The UI fix and a regression test are in source; deploy the UI change, then rerun the rider review flow on the existing order before marking participant reviews complete. No backend fix is currently proposed.

Scope: Ratings, reviews and post-delivery support.

Implementation: `ReviewFlowTest.submitReview` covers customer ratings for the order's restaurant, assigned delivery partner, and purchased dish, plus restaurant and delivery-partner ratings for their permitted order participants. It reopens submitted reviews and checks they are read-only. The rider portion is pending a live rerun after deploying off-duty history access. `CustomerSettingsUiTest.myReviewsTabShowsReviewsOrDefinedEmptyState` checks customer review history, while `deliveredOrderReviewRequiresAtLeastOneRating` verifies the shared modal target list and blocks a no-rating submission. `RiderReviewHistoryApiTest` checks authenticated rider history for an existing order without changing duty or review state. `RestaurantNavigationUiTest.restaurantReviewsShowPublicFeedbackAndAggregate` checks both populated and defined-empty public review states and the outlet aggregate. Backend tests cover ineligible actors, targets, and duplicate submissions. See [validation failures and pending work](PENDING.md) for current results and the live-test boundary.
